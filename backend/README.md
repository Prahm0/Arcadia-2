# Arcadia API

The backend behind the Arcadia app. A Cloudflare Worker: Hono for routing,
Drizzle over D1 for storage, R2 for uploads, OpenAI for Arcad and Resend for
email.

The Next.js frontend never calls this directly from the browser. It proxies
`/api/*` server-side through `app/api/[...path]/route.ts`, so the browser only
ever talks to `arcadiahq.app` and the session cookie stays first-party.

## Layout

```
src/
  index.ts              router, CORS, the auth boundary
  types.ts              Env bindings
  db/schema.ts          Drizzle tables
  lib/
    session.ts          cookie sessions + CSRF check
    password.ts         PBKDF2-SHA256 (bcrypt is not available on Workers)
    crypto.ts           AES-GCM for third-party tokens at rest
    scheduler.ts        turns tasks and commitments into study blocks
    replan.ts           re-plans the current 7-day window
    analytics.ts        streaks and buckets
    serialise.ts        DB rows -> the shapes lib/api/types.ts declares
    openai.ts           chat completion + the propose_changes tool
    email.ts            Resend
    time.ts             timezone maths via Intl, no tz library
  routes/               one file per resource
migrations/             generated by drizzle-kit
smoke.mjs               end-to-end test against `wrangler dev`
```

## Auth

Sign-in sets `arcadia_session`, an HttpOnly, Secure, SameSite=Lax cookie
holding a random token. Only its SHA-256 is stored, so a leaked database does
not hand over live sessions.

Every response that carries a session also carries `csrfToken`. The client
saves it and echoes it in `x-csrf-token` on writes, which a cross-site page
cannot read. `requireSession` rejects any unsafe method without a match.

Routes are protected by default. `src/index.ts` lists the two public prefixes
(`/api/auth/`, `/api/waitlist`); adding a route without touching that list
means it requires a session.

## Scheduling

`rebuildSchedule` runs on every dashboard load and after any change to tasks or
commitments. It materialises sleep and commitments as events, subtracts them
from the day, then fills what is left with study blocks: soonest due first,
capped at `maxDailyStudyMinutes`, in `preferredSessionMinutes` chunks with
breaks between.

Anything the student touched is left alone: pinned blocks, blocks with an
outcome, and anything not marked `source: "auto"`.

## Arcad

`POST /api/chat` streams newline-delimited JSON. Each line is a complete event,
which is what `ArcadView.tsx` parses:

```json
{"type":"message","conversationId":"cnv_...","message":{...},"proposal":{...}}
{"type":"error","message":"Arcad couldn't respond."}
```

Arcad cannot change anything directly. It calls one tool, `propose_changes`,
which writes a pending proposal. Nothing happens until the student hits apply,
and `applyOperations` re-checks ownership on every record it touches.

## Local development

```bash
npm install
npx wrangler d1 migrations apply arcadia --local
npx wrangler dev
node smoke.mjs          # in another terminal
```

Without `OPENAI_API_KEY` the assistant reports itself unconfigured and the rest
of the app works. Without `RESEND_API_KEY`, register returns the verification
token in the response so you can finish sign-up locally.

Put local secrets in `.dev.vars` (gitignored), never in `wrangler.jsonc`:

```
OPENAI_API_KEY=...
RESEND_API_KEY=...
TOKEN_ENCRYPTION_KEY=...
VAPID_PUBLIC_KEY=...
VAPID_PRIVATE_KEY=...
GOOGLE_CLIENT_ID=...
GOOGLE_CLIENT_SECRET=...
GOOGLE_SIGN_IN_ENABLED=true
APPLE_CLIENT_ID=...
APPLE_TEAM_ID=...
APPLE_KEY_ID=...
APPLE_PRIVATE_KEY="-----BEGIN PRIVATE KEY-----\\n..."
REVENUECAT_SECRET_API_KEY=sk_...
REVENUECAT_WEBHOOK_AUTHORIZATION="Bearer <random-long-value>"
```

Google and Apple sign-in stay hidden when their full configuration is absent.
Provider setup and production callback URLs are documented in `DEPLOY.md`.
RevenueCat setup for iOS in-app purchases is documented in
[`../IOS_REVENUECAT_SETUP.md`](../IOS_REVENUECAT_SETUP.md).

## Deploying

`wrangler.jsonc` holds only non-secret config. `database_id` is a placeholder
until the D1 database exists. See `DEPLOY.md` for the full sequence.
